# Система

## Цель системы

Система помогает пользователю регулярно и более осознанно ухаживать за домашними растениями.

Она снижает необходимость самостоятельно помнить график ухода, искать информацию о растениях и вручную определять, когда конкретному растению требуется внимание.

## Границы системы

Система отвечает за:

* ведение коллекции домашних растений пользователя;
* добавление растения по названию или фотографии;
* определение растения по фотографии;
* хранение базовой информации и рекомендаций по уходу;
* формирование первоначального графика проверки необходимости полива;
* хранение истории взаимодействий с растением;
* адаптацию рекомендаций на основе пользовательской обратной связи;
* напоминания о необходимости проверить растение.

Система не отвечает за:

* физическое состояние растения;
* фактическое измерение влажности почвы без внешних устройств;
* гарантированную диагностику заболеваний;
* профессиональные ботанические или медицинские заключения;
* выполнение ухода за растением без участия пользователя.

## Среда системы

Система взаимодействует с внешней средой, в которую входят:

* пользователь;
* домашние растения пользователя;
* мобильное устройство или браузер;
* внешние AI-сервисы;
* сервисы отправки push-уведомлений;
* при необходимости внешние источники данных о растениях.

Эти элементы находятся вне границ системы, но влияют на её работу.

## Входы

Система может получать:

* название растения;
* фотографию растения;
* параметры условий содержания;
* действия пользователя;
* информацию о поливе;
* обратную связь о состоянии почвы или растения.

## Результаты

Система предоставляет пользователю:

* определённый вид растения;
* информацию о растении;
* рекомендации по уходу;
* персонализированный график проверки растения;
* напоминания;
* историю ухода;
* актуальный список растений, которым требуется внимание.

## Основные части системы

На верхнем уровне можно выделить:

* клиентское приложение;
* backend;
* хранилище данных;
* модуль работы с AI;
* механизм планирования и отправки уведомлений.

На данном уровне эти части рассматриваются как крупные элементы системы без детализации их внутреннего устройства.

## Основные связи

Клиентское приложение передаёт пользовательские данные backend-системе и получает от неё актуальное состояние растений.

Backend хранит данные, управляет бизнес-логикой и взаимодействует с внешними AI-сервисами и механизмом уведомлений.

Пользователь взаимодействует с системой через клиентское приложение и одновременно является источником обратной связи, необходимой для адаптации рекомендаций.

## Изменчивость системы

Некоторые части системы могут изменяться относительно независимо.

Например:

* замена AI-провайдера не должна требовать изменения пользовательских сценариев;
* изменение алгоритма расчёта рекомендаций не должно требовать полной переработки frontend;
* изменение способа отправки уведомлений не должно влиять на модель растения;
* изменение интерфейса не должно менять основную бизнес-логику системы.

Поэтому взаимодействия между крупными частями системы должны строиться через явные интерфейсы и контракты.
